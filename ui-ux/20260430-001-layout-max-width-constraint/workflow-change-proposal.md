# 工作流变更提案

---

## 当前问题

管理端内容区布局宽度被错误限制为 `max-w-[1200px]`，与设计规范"弹性填满"要求不符。导致此 bug 的工作流缺陷有三层：

1. **设计产出物内部自相矛盾** — UX 规范文档说"不设限"，但原型 HTML 硬编码 `max-width: 1200px`
2. **开发者以原型为准、未交叉核对规范** — 在大提交中直接照搬原型样式
3. **测试不覆盖视觉合规性** — 无布局断言、无视觉回归测试

---

## 建议变更

### 1. 修复设计产出物矛盾

**问题：** `_bmad-output/archive/v1.2.0/planning-artifacts/` 中，`ux-design-specification.md:486` 和 `prototypes/02-layout-dashboard.html:182` 对内容区最大宽度的定义直接矛盾。

**变更：**
- 修正原型 HTML 中 `.content-area` 的 `max-width: 1200px`，移除该限制
- 在设计规范文档中增加一条明确规则：**布局级样式以规范文档文字描述为准，原型 HTML 仅做视觉参考**

**新增设计规范条目：**
```markdown
### 设计产出物优先级
当原型 HTML 与设计规范文档发生冲突时：
1. 以设计规范文档（.md）文字描述为权威来源
2. 原型 HTML（.html）仅作为视觉辅助参考
3. 发现矛盾时应先修正原型，再实现
```

### 2. 建立设计规范-实现一致性检查流程

**问题：** 开发者在实现时没有交叉对照设计规范的习惯，导致"抄原型抄出 bug"。

**变更：** 在 bmad-pipeline 中增加一个 gate —— **Design Compliance Gate**

**文件：** `.claude/skills/bmad-pipeline/gates/design-compliance-gate.md`

**检查内容：**
1. 布局组件（`layouts/`）的 CSS 类是否包含设计规范中未定义的宽度限制
2. 关键布局 token（max-width、固定宽度）是否与 `ux-design-specification.md` 中的"布局结构"章节一致
3. 原型 HTML 和规范文档之间是否存在矛盾

**触发时机：**
- 修改 `layouts/` 目录下的文件时
- 修改设计产出物（`_bmad-output/`）时

### 3. 布局组件强制测试覆盖

**问题：** `AppLayout.tsx` 是全局布局组件，影响所有页面，但没有单元测试。

**变更：**
- 要求所有 `layouts/` 目录下的组件必须有对应的测试文件
- 测试必须包含"关键 CSS 类断言"——验证布局类名与设计规范一致
- 在 CI 中配置路径守卫：`layouts/` 文件变更时自动运行对应测试

### 4. 大提交拆分策略

**问题：** 引入此 bug 的提交 `9ec18d2` 修改了 50+ 文件，包含重构 + 新功能 + 样式调整，Code Review 时 `max-w-[1200px]` 在大量 diff 中被淹没。

**变更：**
- 单次提交中涉及**布局结构变更**时，必须独立为一个提交
- 布局变更的 commit message 必须包含 `layout:` 前缀，便于检索
- 鼓励按关注点拆分：功能变更、样式调整、布局重构分开提交

## 迁移路径

### Phase 1: 修复 bug（立即）

1. 修改 `AppLayout.tsx:109` 移除 `max-w-[1200px] mx-auto`
2. 修正原型 `02-layout-dashboard.html:182` 移除 `max-width: 1200px`

### Phase 2: 补充测试（同步）

1. 创建 `AppLayout.test.tsx` 验证布局类名
2. 创建 `layout-compliance.spec.ts` E2E 验证宽度
3. 运行全部测试确认通过

### Phase 3: 流程改进（本周内）

1. 在设计规范文档中增加"产出物优先级"条目
2. 创建 Design Compliance Gate 脚本
3. 配置 CI 路径守卫规则

## 经验教训

| 教训 | 防范措施 |
|------|---------|
| 设计原型与规范文档可能自相矛盾 | 建立产出物优先级规则（文档 > 原型） |
| 大提交中细节变更容易溜过 Review | 按关注点拆分提交，布局变更独立 commit |
| 布局组件无测试 = 设计合规无安全网 | 布局组件强制要求单元测试 |
| 视觉 bug 无法被功能测试发现 | 引入视觉回归测试或布局断言 |
