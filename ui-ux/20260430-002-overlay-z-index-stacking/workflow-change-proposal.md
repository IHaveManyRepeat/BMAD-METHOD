# Workflow Change Proposal

## Bug Reference

- **Bug Title**: 弹框蒙层(overlay)遮挡弹框内容(content)

## Current Issue

### 问题描述

项目中没有 z-index 使用规范，开发者在创建 UI 组件时随意使用 Tailwind 默认的 `z-50` 等硬编码值。这导致：

1. 不同语义的元素（蒙层、弹框内容、下拉菜单、浮动提示）共享同一 z-index
2. 新组件开发时无据可依，只能复制现有代码的"魔法数字"
3. z-index 冲突无法通过代码审查发现

### 现有工作流缺陷

- UI 组件开发流程中没有"CSS 层叠上下文"检查步骤
- 代码审查清单中没有 z-index 合规性检查项
- CI pipeline 没有 z-index 静态分析

---

## Proposed Change

### 1. 建立 Z-Index Token 体系（已完成）

在 `admin-frontend/src/index.css` 中通过 Tailwind v4 `@theme` 定义语义化 z-index token：

```css
@theme {
  --z-base: 10;       /* 常规内容区 */
  --z-dropdown: 20;   /* 下拉菜单、Tooltip */
  --z-overlay: 30;    /* 蒙层/遮罩 */
  --z-modal: 40;      /* 弹框内容 */
  --z-toast: 50;      /* Toast 通知 */
}
```

使用方式：`z-overlay`、`z-modal`、`z-dropdown` 等，替代 `z-50`。

### 2. 更新代码审查清单

在代码审查标准中增加：

```markdown
## CSS 层叠检查
- [ ] z-index 是否使用语义化 token（z-base/z-dropdown/z-overlay/z-modal/z-toast）？
- [ ] 蒙层(overlay)是否使用 z-overlay？弹框内容是否使用 z-modal？
- [ ] 是否存在硬编码 z-index（z-50、z-[数字]）？
```

### 3. 添加 CI 检测脚本

在 CI pipeline 中添加 z-index 合规检查，检测硬编码 z-index 用法。
